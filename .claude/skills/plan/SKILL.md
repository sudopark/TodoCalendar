# Plan — TodoCalendar 플랜 작성 컴패니언

**superpowers:writing-plans의 대체가 아니다.** 문서 구조·태스크 분해·TDD 스텝·No Placeholders 원칙은 writing-plans가 이끈다. 이 스킬은 산출 플랜이 **다른 세션 에이전트가 플랜만 보고 착수 가능한 인수인계 문서**가 되도록 프로젝트 종속 요구를 추가한다. 실행 에이전트는 이 세션의 대화·탐색 기억 없이, 플랜에 적힌 것만 갖고 시작한다.

## 전제 — 범위 명확성

플랜은 **후속 이슈 분리가 필요 없을 정도로 확실한 영역**에서 작성한다. 상류(이슈 분해·킥오프 충분성 게이트)에서 경계가 깔끔하게 잘렸다는 전제다.

작성 중 이 전제가 깨지면 — 태스크를 확정할 수 없거나, 스코프 경계가 안 그어지거나, "일단 해보고 판단" 스텝이 필요해지면 — **플랜을 계속 쓰지 말고 멈춰서 유저와 해소한다.** 킥오프 게이트(반문)로 되돌아가는 게 정상 경로다. 범위가 흐린 플랜을 실행자에게 넘기면 우발상황 반문이 빈발한다.

## 필수 섹션

writing-plans 기본 구조(Goal/Architecture/Global Constraints/태스크)에 다음 3개 섹션을 추가한다:

### 1. 스코프 경계 — 헤더 직후

- **건드릴 것 / 안 건드릴 것**을 파일·모듈 단위로 명시한다. 목표·수정 대상·수행 과정은 writing-plans 기본(Goal·Files·Steps)이 커버하므로, 이 섹션의 핵심 추가분은 **"안 건드릴 것"** — 실행자가 범위 밖으로 새는 것을 막는 선이다.

### 2. 커밋 시퀀스 — 태스크 정의 앞

- 최종 커밋 목록을 사전 계획한다: **논리 단위 묶음 + `[#이슈] 동작 변화 요약` 메시지 초안** (CLAUDE.md §5 컨벤션).
- **태스크 경계 ≠ 커밋 경계.** 여러 태스크가 한 커밋으로 묶일 수 있고, 그 대응을 시퀀스에 명시한다 (예: "커밋 2 = Task 2+3").
- 커밋은 결과 위주 — TDD 중간 상태(RED/GREEN 과정)를 커밋에 싣지 않는다. superpowers 태스크 템플릿의 `feat:` 커밋 스텝 대신, 각 태스크의 커밋 스텝이 이 시퀀스의 해당 항목을 참조하게 쓴다.

### 3. 태스크별 모델 티어 — 커밋 시퀀스 뒤

실행 세션이 재판단 없이 그대로 dispatch할 수 있게, 태스크마다 모델 티어를 판정해 표로 명시한다:

- **기계적 transcription** — 플랜에 완전한 코드·내용이 있고 1-2 파일: **하위 모델 (haiku급)**
- **통합·판단** — 멀티 파일 조율, 기존 패턴 매칭, 프로즈 스펙에서 코드 도출: **표준 모델 (sonnet급)**
- **설계 판단** — 아키텍처 결정·광범위 코드베이스 이해 필요: **최상위 모델** (이런 태스크가 있다면 플랜이 덜 여문 신호 — 범위 명확성 전제 재점검)

## 자족성 체크 — 저장 전

플랜 저장 전 아래를 자문한다. 하나라도 "이 세션 기억에만 있다"면 플랜에 옮겨 적는다:

- **목표가 뭐고 뭐를 해야 하는지** — Goal + 태스크 목록으로 답해지는가
- **어디를 수정하고 어디까지가 범위인지** — Files + 스코프 경계로 답해지는가
- **어떤 과정으로 수행하고 어디서 커밋하는지** — 태스크 스텝 + 커밋 시퀀스로 답해지는가
- **탐색으로 알아낸 전제**(현재 동작 file:line, 함정, 오탐 알려진 것)가 Global Constraints나 태스크 본문에 적혀 있는가

## 실행 중 갭

플랜이 커버 못 하는 상황을 실행자가 만나면 implement 스킬의 **플랜 갭 보고 루프**를 탄다 (추측 금지·유저 반문·후속 정리). 이 스킬의 책임은 그 상황이 안 생기게 계획 단계에서 커버를 극대화하는 것까지다.
