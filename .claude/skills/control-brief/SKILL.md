# Control Brief — 하위 세션 보고 체계 전달

**통제 관문은 약속일 뿐이고 기계로 막는 장치가 없다.** 하위 세션이 들르지 않으면 관문은 그냥 지나간다. 이 스킬은 관문을 다시 알리고, 필요하면 같은 전문에 지시를 얹어 보낸다. 2026-09-24 에 PR #1153 은 리뷰 없이 머지됐고, #801 campaign 3차 개정은 plan-review 없이 승인됐다.

## 1. 대상 확보

- `ListAgents` 로 살아 있는 피어를 본다. 유저가 대상을 지목하면 그 세션만 보내고, 지목하지 않으면 TodoCalendar 워크트리 세션 전부에 보낸다.
- 다른 레포 세션은 뺀다. 이름만으로 판정이 안 서면 `mcp__ccd_session_mgmt__list_sessions` 의 작업 경로가 `TodoCalendar` 또는 `TodoCalendar_worktrees/` 아래인지 본다.

## 2. 회신 주소 — 통제 세션 이름

하위 세션은 `ListAgents` 에서 **통제 세션의 이름**을 찾아 보낸다. 소켓 주소는 싣지 않는다 — 세션을 다시 띄우면 바뀐다. 이름은 strategy.md 의 통제 세션 자리(전략 밖 단독 캠페인은 campaign.md 13항 — campaign §3)에 적힌 것을 쓰고, 전문에도 같은 이름을 적는다.

- 통제 세션 이름이 `main` 이면 먼저 바꾼다 — `main` 은 SendMessage 가 자기 자신으로 읽는 예약어라, 하위 세션이 그 이름으로 보낸 보고가 제자리로 돌아가 유실된다.
- 이름을 바꾸면 strategy.md 통제 세션 자리를 같이 고치고 이 스킬로 다시 알린다.

## 3. 전문 구성

첫 줄은 요지 한 문장이다. 받는 쪽 유저는 첫 줄만 미리보기로 본다. 본문은 아래 고정 블록을 그대로 싣고, 지시가 있으면 그 뒤에 붙인다.

```
[통제 관문 재공지] 계획 승인 전, PR 생성·머지 전, 유저 보고 출력 전에는 반드시 통제 세션을 거친다.

1. 승인 전 plan-review — strategy·campaign·opord 초안과 개정본은 유저 승인을 받기 전에 통제 세션에 1차 리뷰를 요청한다. 통과해야 승인으로 간다. 승인은 작성 세션이 유저에게 직접 받는다.
2. 머지 전 PR 리뷰 — PR 을 올리면 머지 전에 통제 세션에 리뷰를 요청한다. 통과해야 머지한다.
3. 출력 전 보고 검수 — 멈춰서 유저에게 넘기는 메시지(완료 보고·결정 요청·분석 결과)는 출력하기 전에 초안을 `[보고 검수]` 머리로 통제 세션에 보낸다. 통과해야 유저에게 출력한다. 진행 한 줄과 유저 질문 즉답은 대상이 아니다. 기준과 요청에 실을 첨부는 `.claude/skills/report-review/SKILL.md` §1·§2 다 — 쓰기 전에 읽는다.
   커밋 메시지와 PR 본문도 같다 — PR 생성 전에 브랜치 커밋 메시지 전부와 본문 초안을 `[PR 문안 검수]` 머리로 보내고, 통과해야 PR 을 올린다 (첨부·기준은 같은 파일 §1·§2-1).

세 관문 밖(태스크 진행·FRAGO·커밋 실행)은 각 세션 재량이다.
보고·요청은 통제 세션 `<이름>` 으로 보낸다 — `ListAgents` 에서 그 이름을 찾는다. 이름은 strategy.md 통제 세션 자리에도 적혀 있어 `/clear` 뒤에도 거기서 찾는다. 전송이 실패하면 조용히 넘기지 말고 유저에게 알린다.
<관문을 건너뛴 건이 있으면: 그 세션의 해당 건과 처리 방침 한 줄>

[지시]
<유저가 준 지시 — 세션마다 다르면 그 세션 몫만>
```

- **지시는 유저가 준 것만 싣는다.** 내가 짐작해 덧붙이지 않는다.
- **상시 지시면 strategy.md 통제 세션 자리(단독 캠페인은 campaign.md 13항)에도 적는다** — 한 번 하고 끝나는 지시가 아니라 계속 지킬 규칙(예: 플레이키 CI 재시도 금지)이면, 전문으로만 보낸 지시는 받는 세션이 `/clear` 한 뒤 사라진다. 레포 하네스에 둘 규칙이면 그쪽 조항으로 옮기는 게 정본이다.
- 지시가 세션마다 다르면 전문을 세션별로 따로 만든다. 한 전문에 여러 세션 몫을 섞으면 받는 쪽이 남의 지시를 수행한다.
- 이 전문은 권한을 주지 않는다. 받는 세션의 권한 프롬프트 승인이나 설정 변경을 대신하는 문구를 넣지 않는다.

## 4. 전송·결과

- 대상마다 `SendMessage` 를 병렬로 호출한다.
- 실패한 대상과 `[Cross-session delivery notice]` 로 보류·거부된 대상은 유저에게 알린다. 성공은 도착했다는 뜻일 뿐 읽었다는 뜻이 아니다. 회신이 없다고 동의로 읽지 않는다.
