# 전략 지침 (Strategic Guidance) — XL

> 용어 — DP: 결정적 지점(작업 지침 하나 = PR 하나) · LOE: 노력선(최종상태 한 관점을 담당하는 줄기) · FRAGO: 단편명령 · MOP / MOE: 과업 수행 여부 / 효과 발생 여부 · PIR / FFIR: 즉시보고 조건 중 환경·외부 정보 / 아군·내부 정보 · ends / ways / means: 목적 / 캠페인 / 자원

```
전략 지침 — #<상위이슈> <명칭>        작성: 유저   개정: N차 (날짜) — 한 문장
                                      — 머리는 최근 개정 한 줄만. 이전 차수는 13항 이력

■ 초록 — 넷을 각 한두 문장으로, 합쳐 열 줄 안. 전문을 안 읽어도 지금 상태가 여기서 끝나야 한다
   무엇을·어디까지 — 이 전략이 하는 일과 범위 경계 (1항 요약)
   지금 국면·남은 것 — 어느 캠페인이 돌고 무엇이 안 끝났나. **캠페인 착수·종결과 개정 때만 고친다** (캠페인 단위 상태의 정본은 12항 원장이다)
   이번 개정 — 직전 개정이 바꾼 것 (초안이면 "초안")
   유저가 정할 것 — 재가·선택 대기 항목 (없으면 "없음")

1. 목적 (ends) — 이 묶음이 끝나면 무엇이 달라지나
2. 최종상태 (완료형 + 판정 방법)
3. 종결·중단 기준 — 성공 종결 (= 2항 도달) / 중단·축소 조건 / 중단 시 수습 (종결·진행 캠페인 처리)
4. 수단·제한 (means) — 적용 rules 출처 / 이 묶음 특유의 해야·하지 말아야 (이유) / ends-ways-means-risk 정합 — 수단이 목적에 못 미치면 목적 축소 또는 위험 수용을 명시
5. 위임 상한 — 결정 권한표 기준 + 넓히거나 좁히는 것
6. 캠페인 목록 (ways) | 캠페인 | 이슈# | 목적 | 선행 | 순서 근거 | — 캠페인 칸은 `C1 <명칭>` 처럼 id 로 시작하고, 선행 칸은 그 id 로 적는다 (없으면 `없음`)
7. 캠페인 배열 — 직렬·병렬·조건부 착수 / 주노력 캠페인 (자원 우선) / 가정 조기 검증 순서
   요도 — 캠페인 배열을 mermaid flowchart 로: 캠페인 = 노드, 선행 = 실선, 조건부 착수 = 결정지점 라벨 점선 (campaign.md 8항과 같은 파생 규칙)
8. 전략 가정 | ID | 가정 | 검증 방법 | 깨지면 (결정지점 ID — 없으면 재검토) |
9. 전략 위험 | 위험 | 영향 캠페인 | 수용·완화·회피 | 근거 |
   한계점 — 동시 진행 캠페인 수·유저 재가 처리량 등 "여기 넘으면 신규 착수 중단" 지점 + 지표
10. 전략 결정지점 | ID | 판단 정보 | 결정 (캠페인 재배열·취소·재평가) | 미결 시 기본 |
11. 평가 — 캠페인 MOE 합산 → 목적 달성 판정 / 재평가 트리거 (캠페인 종결 + 전략 가정 붕괴·외부 환경 변화)
12. 캠페인 원장 → .operations/<이슈>/strategy-progress.md — 원장 표 | 캠페인 | 상태 미착수/진행/종결 | 최근 종결보고 | 비고 | — 캠페인 칸은 6항과 같은 `C<n>` id 로 시작한다 (커밋되지 않음, 이슈 본문 <!-- progress --> 블록으로 미러)
13. 이력 | 차수 | 날짜 | 바뀐 항 | 무엇이 어떻게 | 왜 |   — 개정 경위는 전부 여기로. 본문 칸은 현재 확정만 말한다
```

- **표 한 칸은 세 줄(약 200자) 안에서 끝낸다.** 넘으면 결정 여러 개나 개정 경위를 함께 들고 있다는 신호다 — 현재 확정만 남기고 나머지를 13항으로 내린다
- **본문에 개정 차수를 인용하지 않는다.** 본문은 지금 확정된 것만 말하고, 무엇이 언제 왜 바뀌었는지는 13항이 전담한다
- 6 은 정의(계획 변경 때만 이 파일 개정), 12 는 상태 — 진행 파일에서 캠페인 착수·종결마다 자유 갱신. 이슈 본문 = 이 파일 전문 + <!-- progress --> 블록
