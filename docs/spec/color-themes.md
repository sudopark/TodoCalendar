# 기본 제공 컬러 테마

앱 본체 전 화면에 거는 기본 제공 컬러 테마의 정본이다. 상위 작업은 #461 (C4 컬러 테마 확장)이다.

- 범위는 본체 앱 전 화면이다. 위젯과 공유 확장은 테마를 안 받는다.
- 테마마다 팔레트가 하나다. 시스템 다크모드 추종은 기존 `systemTheme` 이 계속 맡는다.
- 커스텀 테마의 파생 규칙은 이 문서가 다루고, 과금·편집 화면은 범위 밖이다.
- 설정 화면의 저장·복원은 `docs/spec/settings.md` §5 가 다룬다.

## 1. 컨셉

라인업은 19개다. 밝은 계열 11개와 어두운 계열 8개로 나뉜다 (유저 확정 2026-09-22).

**테마를 색 하나에서 파생하지 않는다.** 테마마다 **강조 스케일 · 중립 계열 · 형** 셋을 따로 고르고, 화면 구조를 색 토큰만으로 세 형으로 가른다. 형이 다르면 강조색을 다 지워도 서로 다른 화면이다 — 어두운 계열 `선` 둘만 예외로, 카드 면이 없어 `line` 과 글자가 가른다.

| 형 | 구조 | 밝은 계열 | 어두운 계열 |
|---|---|---|---|
| 채움 | 흰 배경 위에 물든 카드 — 카드가 색으로 떠오르고 글자도 물든다 | 루비 · 자두 · 쪽빛 · 다홍 | 자정 · 와인 · 자수정 |
| 묶음 | 회색조 배경 위에 흰 카드 — 배경이 내려앉고 카드가 뜬다. 글자는 중립이다 | 토마토 · 분홍 · 제비꽃 · 비취 | 심해 · 동백 · 노을 |
| 선 | 밝은 계열은 흰 배경에 배경보다 어두운 카드, 어두운 계열은 카드 면이 없다 | 진홍 · 보라 · 파랑 | 먹 · 황혼 |

### 레퍼런스와 라이선스

색 값은 [Radix Colors](https://www.radix-ui.com/colors) 의 실값을 쓴다. **MIT 라이선스이고 저작권자는 WorkOS 다.** MIT 는 상업적 이용·수정·재배포를 허용하고 색 값 자체에 제약을 두지 않는다.

**Radix 가 지어낸 이름은 테마 이름으로 쓰지 않는다.** MIT 는 이름을 다루지 않아 상표법이 따로 걸리고, 자체 이름으로 가는 것은 유저가 정한 사항이다. 위 표의 `강조 스케일` 칸은 어느 스케일에서 값을 가져왔는지를 밝히는 출처 표기이지 테마 이름이 아니다.

**테마 키 일부가 스케일 이름과 같은 단어인 것은 이 제한에 안 걸린다** — `tomato`·`ruby`·`crimson`·`blue`·`jade` 따위는 색의 일반 명칭이라 Radix 가 만든 말이 아니고, 상표로 독점되지도 않는다. 걸러야 할 것은 지어낸 브랜드명이고(`Solarized`·`Nord`·`Catppuccin`, 그리고 미국 등록상표 6306339 인 `Dracula`), 우리 키 열아홉에는 그런 이름이 없다. 이 판정은 한 번 상신돼 확정됐다 (2026-09-22).

Radix 스케일은 12단계이고 단계마다 쓰임이 정해져 있다 — 1 앱 배경 · 2 보조 배경 · 3 컴포넌트 면 · 5 선택된 면 · 6 구분선 · 9 솔리드 브랜드색 · 11 보조 글자 · 12 본문 글자. 중립 계열은 여섯(`gray`·`mauve`·`slate`·`sage`·`olive`·`sand`)이라 회색의 온도까지 고른다.

## 2. 팔레트

테마 19개 × 토큰 33개의 확정값이다 (유저 승인 2026-09-22 — 밝은 계열·어두운 계열 두 라운드). 이 표가 DP-1.4 파생 규칙의 입력이다.

**기본 이벤트 태그 두 색은 팔레트 밖이다** — 유저 설정값이라 테마가 안 건드리고, 배경(`bg0`)과 월 캘린더 면(`dayBackground`) 위에서 읽히는지만 본다. 카드면(`bg1`) 위 가독성은 DP-3.2 실기 확인으로 넘겼다 (근거는 §3).

### 형별 파생 규칙

라인업이 정한 것은 열 토큰(`bg0`·`bg1`·`todayBackground`·`line`·`text0`·`text1`·`accent`·`selectedDayBackground`·`selectedDayText`·`holidayOrWeekEndWithAccent`)이고, 나머지 스물셋을 아래 규칙으로 채웠다.

- **채움** — 배경은 중립 1단계, 카드는 **강조 3단계**다. 카드가 색으로 떠오르고 글자도 강조 계열이라 물든다. `bg2`·`secondaryBtnBackground` 는 강조 5단계, `line` 은 카드와 같은 값이라 테두리가 안 보인다.
- **묶음** — 배경은 중립 3단계(어두운 계열은 1단계), 카드는 흰색(어두운 계열은 중립 3단계)이다. 배경이 내려앉고 카드가 뜬다. 글자는 중립 계열이라 안 물든다. `bg2` 는 중립 2단계, `line`·`secondaryBtnBackground` 는 중립 6단계다.
- **선** — **밝은 계열**은 배경이 중립 1단계, 카드가 **중립 3단계**다 — 카드가 배경보다 어둡다(묶음과 방향이 반대다). **어두운 계열**은 배경과 카드가 같은 값이라 카드 면이 없다 — 중립 1단계가 이미 가장 어두워 더 내릴 자리가 없다. `bg2` 는 중립 2단계, `line`·`secondaryBtnBackground` 는 중립 6단계다.

관계로 채운 것은 `dayBackground`=`bg0`, `weekDayText`·`holidayText`=`text0`, `weekEndText`=`text1`, `eventTextSelected`·`aiUserBubbleText`=`selectedDayText`, `aiUserBubbleBackground`=`selectedDayBackground`, `secondaryBtnText`=`text0`, `primaryBtnBackground`=`accent`, `text0_inverted`=밝은 계열 `bg0`·어두운 계열 `bg2` 다.

**3차 글자 사다리** — `text2`·`placeHolder` 는 보조 글자(`text1`)에서 구분선(`line`) 쪽으로 물러나되, 출시 라이트가 서 있는 비율을 바닥선으로 지킨다 (`text2` 2.96:1 · `placeHolder` 1.54:1, 흰 배경 기준). 끝점이 형마다 달라 채움은 물든 채로 옅어지고 묶음·선은 회색으로 옅어진다.

**AI 두 토큰** — `accentAI` 는 `accent` 에 `#7C5CFA` 를 40% 섞고, `primaryBtnText` 대비 3:1 미달이면 OKLCH 밝기를 조정한 값이다. `aiListeningBackground` 는 그 색의 OKLCH 색상 −40°·0·+40° 세 색(채도 하한 0.08)에 계열별 투명도(밝은 계열 20·13·20%, 어두운 계열 28·18·26%)를 입힌다. 어두운 계열은 같은 강조 스케일을 쓰는 밝은 테마와 값이 같다.

**관계가 깨지는 자리 셋** — `secondaryBtnBackground` 는 중성 회색 고정값이 글자와 4.5:1 을 못 넘어 형별로 정했다. `eventText` 는 `text1` 을 물려받되 채움 형 넷에서 `todayBackground`(같은 강조 스케일의 5단계)와 4.5:1 을 못 넘어, 본문 글자 쪽으로 최소한 물린 값을 테마별로 적었다. `primaryBtnText` 는 흰색이 기본인데 **먹** 한 테마에서만 배경색(`#111111`)으로 바뀐다 — 그 테마는 강조색까지 중립에서 뽑아 `primaryBtnBackground` 가 `#B4B4B4` 라, 흰 글자를 얹으면 2.07:1 로 3:1 을 못 넘고 검은 글자면 9.11:1 이다.

### 출처 표기

- **라인업** — T-1 에서 유저가 승인한 값
- **상속** — 출시 라이트·다크 테마(`ColorSetKeys+Definition.swift`)의 토큰 관계에서 물려받은 값
- **명시** — 관계로 안 풀려 형별·테마별로 정한 값
- **고정** — 테마와 무관한 공통 상수
- **파생** — `accent` 에서 계산한 값

출시 라이트·다크도 라인업과 같은 정의 구조이고, 관계와 어긋나는 토큰은 override 로 담는다. 토큰 이름 옆 괄호가 그 토큰의 출처이고, 테마마다 갈리는 토큰은 괄호가 없으며 관계·상수에서 벗어난 칸에 `*` 를 붙였다.

### 커스텀 테마 파생

유저가 고른 시드 색과 형에서 `ColorThemeDefinition` 을 만드는 규칙이다. 구현은 `CustomColorThemeBuilder.build(name:seeds:)` 이고, 같은 입력에는 늘 같은 정의를 낸다.

**입력** — 시드 여덟과 형 하나다.

| 시드 | 필수 | 들어가는 토큰 |
|---|---|---|
| 배경 | 필수 | `bg0` |
| 강조 | 필수 | `accent` |
| 글자 | 선택 | `text0` (`text1` 은 아래 글자 시드 규칙) |
| 카드 | 선택 | `bg1` |
| 오늘 | 선택 | `todayBackground` |
| 선택일 | 선택 | `selectedDayBackground` |
| 주말·공휴일 | 선택 | `holidayOrWeekEndWithAccent` |
| AI | 선택 | `accentAI` (`aiListeningBackgroundBase` 는 여기서 파생) |

형은 채움·묶음·선 셋이고, 계열(밝음·어둠)은 보정된 `bg0` 의 `isLight` 로 정한다.

**배경 구간** — 배경 시드의 상대휘도가 0.0218 초과 0.8161 미만이면 가까운 경계에 닿을 때까지 OKLCH 명도만 옮긴다. 밝은 구간은 0.8161 이상, 어두운 구간은 0.0218 이하다. 기본 태그 `#088CDA`·`#D6236A` 가 배경 위에서 3:1 을 넘는 경계가 이 두 값이고, 라인업 배경 19개는 전부 구간 안이다. 카드 시드도 같은 계열 구간에 넣는다.

**명도 사다리** — 라인업 19개에서 같은 형·계열 토큰의 OKLCH 명도를 `bg0` 명도와의 차이로 재고, 그 중앙값을 형 × 계열별 상수로 쓴다. 채도 상한도 같은 방식으로 쟀다. 중립 토큰은 배경 hue 를, 강조 토큰(`today`·`selectedDayBackground`·`holidayOrWeekEndWithAccent`, 채움 형의 `bg1`·`bg2`·`line`·`secondaryBtnBackground`·`text0`·`text1`·`text2`·`placeHolder`)은 강조 hue 를 따른다. `text2`·`placeHolder` 는 모든 계열에서 `bg0` 대비 2.96:1·1.54:1 이상이 되게 한다. 값은 출시 라이트가 서 있는 비율이다.

**글자 시드 규칙** — `text` 시드는 `text0` 이 된다. `text1` 은 그 시드의 hue·채도를 따르고, 명도는 시드 명도에 사다리의 `text1`−`text0` 차이를 더한 값이다. 글자 시드가 없으면 사다리 값을 쓴다.

**보정 순서** — 아래 순서로 한 번씩 돈다. 앞 단계가 고친 색을 뒤 단계가 다시 바꾸지 않는다. 쌍마다 정해진 한쪽만 OKLCH 명도를 0.01 씩 옮기며, 방향은 배경에서 멀어지는 쪽이다 (배경 상대휘도 0.18 이상이면 어둡게, 미만이면 밝게). 유저가 고른 시드도 대비가 모자랄 때만 움직인다. 명도를 끝까지 옮겨도 못 넘으면 그 방향의 순백·순흑을 쓴다. 다만 `todayBackground` 당기기와 AI 토큰은 이 규칙을 따르지 않고 범위 끝 후보를 그대로 쓴다.

1. `accent` / `bg0` 3:1
2. `text0` → `text1` 이 각각 `bg0`·`bg1` 4.5:1
3. `holidayOrWeekEndWithAccent` / `bg0` 3:1
4. `eventText` / `todayBackground` 4.5:1 — `text1` 이 못 넘으면 `eventTextOverride` 로 따로 보정하되 `bg0` 4.5:1 도 지킨다. 둘을 함께 못 지키면 `todayBackground` 를 `bg0` 명도 쪽으로 당긴다
5. `selectedDayText` — 흰색·검정 중 `selectedDayBackground` 와 대비가 큰 쪽이다. 둘 중 하나는 늘 4.58:1 이상이라 배경은 안 움직인다
6. `secondaryBtnBackground` / `text0` 4.5:1 — `text0` 은 공유 토큰이라 고정하고 배경 쪽이 `text0` 에서 멀어진다
7. `primaryBtnText` / `accent` 3:1 — 흰색이 못 넘으면 검정을 `primaryBtnTextOverride` 로 둔다

**AI 토큰** — AI 시드가 있으면 그 색이 `accentAI` 의 출발점이다. 없으면 `accent` 에 `#7C5CFA` 를 sRGB 채널 선형 보간으로 40% 섞은 색에서 출발한다. 어느 쪽이든 `primaryBtnText` 대비 3:1 미만일 때만 OKLCH 명도를 0.02 씩 옮긴다. `primaryBtnText` 가 흰색이면 어둡게, 검정이면 밝게 옮기고 명도 범위는 0.05~0.98 이다. `aiListeningBackgroundBase` 는 `accentAI` 의 OKLCH hue −40°·0°·+40° 세 색이고 채도 하한은 0.08 이다.

**검증** — `CustomColorThemeContrastGridTests` 가 §3 대비 19검사에 `accentAI`/`primaryBtnText` 3:1 을 더한 20검사를 격자 전수로 확인한다. 격자 A 는 필수 시드만, 격자 B 는 AI 를 포함한 선택 시드에 배경과 같은 색·강조와 같은 색·흰색·검정을 넣은 조합이다. 배경 명도 표본에는 구간 밖(중간 명도)이 들어 있어 구간 고정 경로도 지난다.

### 커스텀 테마 저장

**식별** — 선택값(`color_set`)은 `custom:<uuid>` 로 저장한다. `custom:` 뒤가 빈 문자열이면 알 수 없는 값이다. 선택값은 서버와 동기화하지 않는다.

**저장 매체** — 계정별 DB 의 `CustomColorThemes` 테이블이다. 로그인 유저에게 이 테이블은 서버의 캐시다(아래 동기화). DB 파일이 계정 단위라 user 컬럼이 없고, 로그아웃하면 미로그인 DB 를 다시 열기 때문에 로그인 계정의 테마는 미로그인 화면에 보이지 않는다. 같은 uuid 를 저장하면 덮어쓰고 목록은 `created_at` 오름차순이다.

**필드** — `uuid`·`name`·`schema_version`(현재 1)·`seeds`·`colors`·`created_at`·`updated_at`(Unix 초)이다. `seeds` 와 `colors` 는 JSON 텍스트 한 칸이다.
- `seeds` 키는 `background`·`accent`·`text`·`surface`·`today`·`selectedDay`·`holidayOrWeekEnd`·`ai`·`form`(`filled`·`grouped`·`outlined`)이다. 색은 `#RRGGBB` 이고, 없는 선택 시드는 키를 뺀다.
- `colors` 는 `ColorThemeDefinition.exportedColors` 가 펼친 `#RRGGBB` 맵이다. 서버 필수 필드라 저장하는 쪽이 저장 시점에 계산해 함께 둔다. 화면은 `colors` 를 읽지 않고 시드에서 매번 파생한다.

**동기화** — 로그인 유저의 테마는 서버 `/v2/setting/color_themes` 에 저장한다(`CustomColorThemeRemoteRepositoryImple`). 저장·삭제는 서버가 성공해야 캐시에 반영하고, 서버가 실패하면 에러를 내고 캐시를 안 바꾼다. 목록 조회는 서버 목록으로 캐시를 통째로 갈아 끼우고 `created_at` 오름차순으로 돌려준다. 서버가 실패하면 캐시 목록을 돌려주므로, 다른 기기에서 지운 테마가 잠깐 남아 보일 수 있다. 단건 조회와 앱 시작은 캐시만 읽는다. 비로그인 유저는 서버를 거치지 않는다.

**그리기** — 현재 선택된 커스텀 테마 하나는 calendar 외형 설정(`CalendarAppearanceSettings.currentCustomColorTheme`)에 담겨 설정 통지로 흐른다. 키가 `custom:<uuid>` 이고 uuid 가 같은 테마일 때만 채우며, UserDefaults 에는 저장하지 않는다(정본은 DB 다). `ViewAppearance` 는 테마 목록을 들지 않고 그 테마 하나(`customColorTheme`)만 든다. `ColorSetKeys.convert(isSystemDarkTheme:customColorTheme:)` 는 키의 uuid 와 테마의 uuid 가 같고 필수 시드가 `#RRGGBB` 로 읽힐 때만 시드로 파생한 정의를 내고, 아니면 시스템 테마로 그린다. 이 폴백 동안엔 창 스킴을 강제하지 않고 기기 라이트·다크 전환을 따른다 (`ViewAppearance.isFollowingSystemTheme`). 선택값은 계정과 무관한 전역 설정이라 로그아웃·계정 전환 뒤 그 id 가 새 계정에 없을 수 있다.

**읽는 시점** — 앱을 켤 때는 DB 를 먼저 열고, 외형 설정을 읽으면서 선택값이 커스텀이면 그 테마 하나만 읽어 설정에 담는다. 계정이 바뀌면 DB 를 다시 연 뒤 저장된 설정 키가 커스텀일 때 새 계정 DB 에서 그 테마 하나를 읽어 store 에 갈아 끼우고 루트 화면을 새로 만든다. 메인 화면이 외형 설정을 새로 읽을 때도 같은 방식으로 채운다.

**관리** — 테마 목록 조회·저장·삭제는 `UISettingUsecase`(`loadCustomColorThemes`·`saveCustomColorTheme`·`removeCustomColorTheme`)가 맡고, 목록은 메모리에 올리지 않고 커스텀 테마 화면이 직접 조회한다. 커스텀 테마를 고를 때는 `selectCustomColorTheme`이 키와 그 테마를 함께 넣어 통지한다. 저장한 테마가 현재 선택이면 usecase 가 calendar 설정의 현재 테마를 갈아 끼워 설정 통지를 보내고, 삭제한 테마가 현재 선택이면 선택 키를 시스템 테마로 되돌리고 설정 통지를 보낸다. 그 외에는 통지하지 않는다. 폰트처럼 다른 항목만 바꿔도 키가 그대로면 들고 있던 현재 테마를 이어 담고, 다른 커스텀 키로 바뀌면 비운다.

## 4. 사용권

무료 유저가 유료 테마를 쓰는 권리다. 판단은 `PaidFeatureGateUsecase`(`Domain/Sources/Usecases/Billing/PaidFeatureGateUsecase.swift`)의 컬러 테마 요건 메서드에서 내리고, 선택 화면·생성 저장·앱 시작 게이트는 이 답만 읽는다. 사용권은 전체 테마에 하나다 (#1197).

무료 테마는 `.systemTheme`·`.defaultLight`·`.defaultDark` 다. `.appTheme(_)` 와 커스텀 테마는 유료 테마다.

### 판정표

| plan 상태 | 무료 테마 | 유료 테마, 사용권 유효 | 유료 테마, 사용권 없음·만료 |
|---|---|---|---|
| 보류 | 허용 | 허용 | 허용 |
| 유료 | 허용 | 허용 | 허용 |
| 무료 | 허용 | 허용 | 광고 필요 |

- **보류**는 둘 중 하나다. plan 을 아직 못 받았거나(`latestUserPlan() == nil`), 앱이 모르는 plan 이라 `isPaid == nil` 이다. 보류에는 광고도 게이트도 요구하지 않는다. 정책을 받지 못한 상태는 보류가 아니다. 기본 정책으로 판정한다.
- 정책의 `enabled` 가 `false` 이면 게이트를 끈 것이라 허용한다.
- 소비자는 `canApplyColorThemeWithoutAd` 가 `false` 일 때 광고를 띄운다. 별도 게이트 판정 메서드는 없다. 유료 → 무료로 돌아와도 별도 상태 없이 기록된 부여 시각으로만 판정하므로, 남은 기간이 있으면 그대로 유효하다.
- 테마 생성 광고 판정도 `PaidFeatureGateUsecase` 에 요건 메서드로 더한다. 기능 enum 같은 일반화는 하지 않는다.

### 만료 기산

`grantColorThemeLicense(at:)` 가 기존 기록을 부여 시각으로 덮어쓴다. 사용권은 `부여 시각 <= now < 부여 시각 + n×24시간` 일 때만 유효하다. 달력 일수가 아니라 24시간 단위로 센다.

### 기본값과 속성별 폴백

기본 정책(게이트 켜짐·7일)은 앱이 정의해 `PaidFeatureGateUsecase` 에 주입한다(`AppEnvironment.defaultAppPolicy`). 번들 파일로 들고 있지 않다. 원격 정책(`app-policy.json` 의 `color_theme_license`, 스키마는 `infrastructure.md` §9)에서 판단할 수 없는 속성만 기본값을 쓴다. `enabled` 와 `license_days` 를 각각 본다.

| 원격 정책 상태 | enabled | license_days |
|---|---|---|
| 정책 자체가 없음(아직 못 받음)·항목 없음 | 기본값 | 기본값 |
| `enabled` 만 없음 | 기본값 | 정책 값 |
| `license_days` 가 없거나 0 이하 | 정책 값 | 기본값 |
| 둘 다 유효 | 정책 값 | 정책 값 |

`enabled` 가 `false` 이면 기간과 상관없이 허용한다. 원격 설정 실수 하나로 사용권 광고가 통째로 꺼지지 않게, 판단할 수 없는 속성은 기본값으로 채운다. 기본값으로도 판단할 수 없으면 허용한다. 앱 정책 갱신 호출은 앱 시작 쪽 작업이 맡는다.

### 기록

사용권 기록은 기기 로컬(`EnvironmentStorage`)에만 둔다. 계정 전환이 `EnvironmentStorage` 를 지우지 않으므로 계정 A 에서 받은 사용권이 계정 B 에서도 유효하다.
