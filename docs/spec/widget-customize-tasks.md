# 단계 3 과업과 최종 모습

> #1086 단계 3(수평 확장)에서 실제로 할 일과, 끝났을 때 유저가 보게 될 모습.
> 범위 정본은 [`widget-style-items.md`](widget-style-items.md). 2026-09-16 유저 결정 반영.
> 확정되면 campaign 2항·8항·9항을 개정한다.

## 1. 층 구조

| 층 | 무엇 | 저장처 | 적용 |
|---|---|---|---|
| 전역 배경색 | 배경색 하나 | `WidgetAppearanceSettings.background` | 전 위젯 기본값 |
| 스타일 배경색 | 같은 배경색 | `WidgetStyle` 봉투 | 그 스타일을 건 위젯 — 전역을 덮는다 |
| 표시 토글 | 위젯군별 요소 | `WidgetStyleSetting` payload | 그 위젯군 |

색은 **배경색 하나**다. 글자색은 배경 밝기에서 자동으로 따라가고 유저가 고르지 않는다 — 안 보이는 위젯이 만들어질 수 없다.

**배경색이 스타일에 들어가므로 전 위젯군이 스타일을 갖는다.** 토글이 0인 EventList·DDay·Composed 도 배경색으로 꾸밀 수 있고, 인스턴스마다 다른 배경을 건다. "배치형 전 위젯 `AppIntentConfiguration`" 최종상태(campaign 4항)가 그대로 선다.

해석 순서는 인스턴스 스타일 배경색 → 변형 기본 스타일 배경색 → 전역 배경색 → 시스템 기본이다. 표시 토글의 기존 순서(인스턴스 커스텀 > 변형 기본 > 초기값, DP-2.3 확정)에 전역 단이 하나 끼는 것이고, 그 단은 배경색에만 있다.

## 2. 과업

### A. 배경색 층

전역 배경색 편집 화면은 이미 있다(설정 > 외형 > 위젯). 이번에 느는 것은 **위젯별 배경색**이다.

| 과업 | 내용 |
|---|---|
| A-1 | `WidgetStyle` 봉투에 `background: WidgetAppearanceSettings.Background?` 를 더한다. nil 이 "전역 따름"이다 |
| A-2 | 배경색 편집 UI — 편집 뷰모델이 봉투를 다루므로 **한 벌만 만든다.** 위젯군마다 만들지 않는다 |
| A-3 | provider 와 뷰가 해석 순서대로 배경색을 받는다. 글자색은 지금처럼 배경 밝기에서 따라온다 |
| A-4 | **DDay 뷰 ColorSet 정합** — 홈 변형까지 `.primary`/`.secondary` 고정이라 배경색조차 글자에 반영이 안 된다. 이게 빠지면 DDay 만 배경을 바꿔도 글자가 안 따라온다 |
| A-5 | 갤러리 1·2뎁스 프리뷰가 배경색을 반영한다 |

### B. 위젯군별 스타일

각 위젯군이 같은 모양의 과업 넷을 갖는다.

1. **payload 타입 신설** — `XxxStyleSetting`. 토글이 0인 위젯군은 빈 구조체다 (배경색은 봉투에 있다).
2. **편집 폼 신설** — `XxxStyleFormView`. `(setting, onChange)` 를 받고 자체 상태를 갖지 않는다 (DP-3.0 계약). 토글이 0이면 폼도 없고 배경색 섹션만 뜬다.
3. **전환·파라미터** — `StaticConfiguration` → `AppIntentConfiguration`, AppEntity·EntityQuery·스타일 파라미터.
4. **provider 해석** — 인스턴스 커스텀 > 변형 기본 > 초기값 (DP-2.3 확정).

**변형 여럿이 kind 하나를 공유하는 구조가 흔하다.** EventList 3변형 · Foremost 3변형(홈 2 + inline 1) · AICommand 2변형(홈 1 + circular 1)이 각각 kind 하나를 쓴다. 저장 좌표는 변형 단위인데 인스턴스 파라미터는 kind 단위라, 좌표 해석이 DP-3.2 의 중심 결정이다 — 편집 화면을 좌표 집합으로 여는 DP-3.0 설계가 선택지를 남겨둔다.

**잠금화면 인스턴스의 편집 시트에도 "스타일" 줄이 뜬다.** kind 하나에 Configuration 이 하나라 같은 kind 의 잠금화면 변형이 Intent 를 물려받고, 가릴 수단이 없다(`parameterSummary` 의 `When` 은 파라미터 값만 비교하고 family 는 파라미터가 아니다). 위젯 선언을 쪼개면 kind 가 갈려 배치된 위젯이 죽는다(A1 위반). 그대로 받고 provider 가 잠금화면 family 에서 좌표를 무시한다 — 잠금화면은 애초에 꾸밀 항목이 없어 모양이 안 바뀐다 (유저 결정 2026-09-17, DP-3.2 수용 위험).

| 위젯군 | 토글 | 전환 | 폼 |
|---|---|---|---|
| Month | 4 | 1개 | 필요 |
| WeekEvents | 2 (7변형 공유) | 7개 | 필요 |
| TodayAndNext | 1 | 이미 AppIntent | 필요 |
| Foremost | 1 | 홈 2개 | 필요 |
| AICommand | 1 | 홈 1개 | 필요 |
| EventList | 0 | 이미 AppIntent | 없음 — 배경색만 |
| DDay | 0 | 이미 AppIntent | 없음 — 배경색만 |
| Composed | 합성별 (하위 payload 를 담는다) | 4개 | 필요 — 제 스타일이 두 절반 토글과 배경색을 갖는다 |

### C. 별건

| 과업 | 내용 |
|---|---|
| C-1 | **DDay 사진 배경** — App Group 이미지 저장·다운샘플, 배경 적용 지점 확장, 사진 위 대비 보정. A2·A6 가정을 spike 로 판정하고 D2 결심으로 간다 |
| C-2 | **Composed 제 스타일** — 합성 스타일이 두 절반의 표시 토글과 배경색을 갖는다. 하위 스타일과는 끊긴다 (#1133) |

## 3. DP 재편안

| DP | 내용 | 선행 | 사이즈 |
|---|---|---|---|
| **DP-3.0** | 표현 층 payload 일반화 (재가 완료, 착수 대기) | 2.3 | M |
| **DP-3.A** | 배경색 층 — 봉투 배경색 · 편집 UI 한 벌 · 해석 · DDay ColorSet 정합 · 프리뷰 | 3.0 | M |
| **DP-3.1** | Month + WeekEvents — payload·폼·전환 8·파라미터 | 3.0 | M |
| **DP-3.2** | TodayAndNext + EventList + Foremost + AICommand — payload 4·폼 3·전환 3·파라미터 | 3.0 | M |
| **DP-3.4** | DDay — 색 정합 확인 + 사진 배경 | 3.A | M |
| **DP-3.5** | Composed — 합성 payload·편집 폼·전환 4·파라미터 + 토글 OFF 스냅샷 | 3.1 · 3.2 | M |

**DP-3.3 은 사라진다** — Foremost·AICommand 가 3.2 로 흡수되고, NextEvent 계열은 잠금화면 전용이라 대상 밖이다.

**DP-3.A 와 DP-3.1·3.2 는 편집 화면을 함께 만진다.** DP-3.A 가 배경색 섹션을 더하고 위젯군 DP 가 폼을 더하는데 둘 다 `WidgetStyleEditView` 를 건드린다. 병렬로 열면 rebase 가 필요하다 — 8항 통제수단(머지 순서 선언·뒤 브랜치가 rebase 전담)이 이 경우를 덮는다.

## 4. 끝났을 때 — 유저가 보는 것

### 배경색을 전체에 걸거나 위젯마다 따로 건다

설정 > 외형 > 위젯에서 배경색을 고르면 홈 위젯 전부가 그 색이 된다. 갤러리에서 위젯 하나를 골라 **그 위젯만 다른 배경색**으로 둘 수도 있다. 안 건드린 위젯은 전체 설정을 그대로 따라온다.

글자색은 배경에 맞춰 알아서 바뀐다 — 어두운 배경을 고르면 글자가 밝아진다. 유저가 따로 고르지 않는다.

잠금화면 위젯은 시스템이 색을 강제해서 그대로다.

### 위젯 종류마다 보여줄 항목을 고른다

- **Today** — 공휴일 이름 · 타임존 · 월/년 · 총 개수 · 할일 개수 · 일정 개수
- **Month** — 월 이름 · 요일 헤더 · 오늘 강조 · 이벤트 밑줄
- **WeekEvents** — 월 텍스트 · 요일 헤더 (7종이 같은 설정을 쓴다)
- **TodayAndNext** — 타임존
- **Foremost** — "가장 중요한 일정" 라벨
- **AICommand** — 설명 문구
- **EventList · DDay** — 켜고 끌 항목은 없고 배경색만 고른다
- **Composed** — 두 절반의 표시 토글을 제 스타일로 갖는다 (#1133)

고치는 즉시 미리보기가 바뀌고, 저장하면 홈 위젯도 다음 갱신에 따라온다.

### 스타일을 여러 개 만든다

같은 위젯 종류에 대해 배경색과 표시 항목을 묶어 여러 벌 만들고 이름을 붙인다. 하나를 복사해 조금 바꿔 다른 스타일로 둘 수 있다.

### 홈 위젯마다 다른 스타일을 건다

홈 화면에서 위젯을 길게 눌러 편집하면 "스타일" 줄이 뜬다. 거기서 만들어둔 스타일을 고르면 그 위젯만 그 모양이 된다. **같은 종류 위젯 두 개를 나란히 놓고 서로 다르게 꾸밀 수 있다** — 배경색이든 표시 항목이든.

고른 스타일을 앱에서 지우면 그 위젯은 종류의 기본 스타일로 돌아간다.

### 꾸미기를 안 건드린 위젯은 그대로다

기본값 경로는 지금 모양·동작과 같다. 스냅샷으로 대조한다.

## 5. 확정 사항

| 항목 | 결정 |
|---|---|
| 색 | 배경색만 — 위젯별 지정 + 전체 적용 |
| 글자색 | 범위 밖 — 배경 밝기에서 자동 |
| 배경색 저장 위치 | `WidgetStyle` 봉투 — 편집 UI 한 벌 |
| DP 재편 | DP-3.3 소멸 · DP-3.A 신설 · DP-3.2 에 EventList 흡수 |
| AICommand 설명 문구 토글 | 유지 |

남은 결정은 없다. campaign 8항(배열·요도)·9항(DP 목록)을 개정하고 DP 이슈를 다시 짠다 — 2항은 텍스트 색을 안 열기로 해서 개정이 필요 없다.
