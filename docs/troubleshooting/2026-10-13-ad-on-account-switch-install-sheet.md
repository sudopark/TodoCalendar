# 계정 전환으로 설정 화면이 내려가면 전면광고가 떠 앱 설치 시트까지 보인다

- **증상**: 로그인·로그아웃으로 루트 화면이 교체되는 동안 전면광고가 뜨고, 그 광고의 App Store 설치 시트가 전환 중 화면 위에 남는다. 설정 화면을 거쳤을 때만 난다.
- **근본 원인**: `MainRouter` 는 `SettingNavigationController.viewDidDisappear` 의 `isBeingDismissed` 를 전면광고 트리거로 쓴다. 루트 교체도 이 플래그를 세우므로 트리거가 똑같이 당겨진다. #1164 가 넣은 `FullScreenAdRouterImple.show` 의 `viewIfLoaded?.window != nil` 가드는 이것을 막지 못했다 — 닫힘 콜백이 `window.rootViewController` 대입이 끝나기 전에 동기로 들어와, 그 턴에는 옛 화면이 아직 윈도우의 루트로 남아 가드를 통과한다. 실측값은 아래와 같다.

  | 시점 | 루트 교체 | 유저가 직접 닫음 |
  |---|---|---|
  | `onDismissed` 안 | 윈도우 있음 · 루트 == 옛 화면 | 윈도우 있음 · 루트 == 화면 |
  | 한 턴 뒤 | 윈도우 없음 · 루트 ≠ 옛 화면 | 윈도우 있음 · 루트 == 화면 |

- **해결**: `FullScreenAdRouterImple.show` 가 윈도우 판정부터 노출·기록까지를 메인 액터 한 턴 뒤로 미룬다. 가드의 술어는 그대로 두고 평가 시점만 옮겼다. 전면광고를 띄우는 세 자리(설정 이탈·공유 완료·앱 실행)가 모두 이 메서드를 지나므로 자리마다 가드를 심지 않는다.
- **기각 방향**: 전환 중 상태를 `handleUserSignedIn`·`handleUserSignedOut` 에서 세워 그동안 노출을 억제한다 — 닫는 시점에 두 경우를 가를 신호가 없다는 전제에서 세운 안인데, 한 턴 뒤에는 갈린다는 실측으로 전제가 깨졌다. 상태를 두면 `adExposureUsecase` 가 유즈케이스 팩토리마다 새로 만들어지는 탓에 앱 수명 보관처를 따로 세워야 하고, 루트 교체 경로를 핸들러별로 열거해야 한다.
- **기각 방향**: 닫힘 콜백 안에서 "내 화면이 아직 윈도우의 루트인가" 를 확인한다 — 그 시점에는 두 경우의 답이 모두 참이다.
